Distributed lookups when applications can provide the full key and traffic can spread evenly. A similar-looking predicate may not use the same access path; operators, expressions, key order, and data type all matter.

Read Performance, Storage, and Write Costs

Low-cardinality or time-only keys can create hot partitions; many tiny partitions add overhead. Indexes reduce some search work but require storage and add maintenance to writes.

Partition Keys Limitations and Common Mistakes

Equality on only part of a composite partition key generally cannot route to one partition.

Do not assume that an index being present means the optimizer chose it or that the query became selective.

Partition Keys Questions

Will the database always use this index?

No. The optimizer weighs selectivity, estimated costs, statistics, cache state, and the amount of data returned.

What should I verify before production?

Confirm version support, query compatibility, write overhead, build/rollback procedures, and index behavior during backup and recovery.
