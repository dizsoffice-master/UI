Lesson 10: Measure before optimizing

Use the query plan to find expensive scans, joins, sorts, and estimates that differ from actual row counts. Indexes speed some reads but consume storage and add write cost.

EXPLAIN (ANALYZE, BUFFERS)
SELECT customer_id, SUM(total)
FROM orders
WHERE order_date >= DATE '2025-01-01'
GROUP BY customer_id;

EXPLAIN ANALYZE executes the query. Use it carefully for statements with side effects; PostgreSQL supports wrapping experiments in a transaction and rolling back.

Capstone: customer order report

Build a report showing each customer, paid-order count, lifetime revenue, most recent order, and rank within their region. Use a CTE to aggregate orders, join customers and regions, and a window function to rank totals. Validate with a small known dataset, then inspect EXPLAIN for the production-sized query.

WITH totals AS (
  SELECT customer_id, COUNT(*) AS order_count, SUM(total) AS revenue,
         MAX(order_date) AS latest_order
  FROM orders
  WHERE status = 'paid'
  GROUP BY customer_id
)
SELECT c.name, t.order_count, t.revenue, t.latest_order,
       RANK() OVER (PARTITION BY c.region_id ORDER BY t.revenue DESC) AS region_rank
FROM totals t
JOIN customers c USING (customer_id)
ORDER BY c.region_id, region_rank;

SQL dialect note

This course uses PostgreSQL syntax for examples such as ILIKE, RETURNING, identity columns, date_trunc, and JSONB. SQL Server, MySQL, SQLite, and Oracle differ in functions, paging syntax, data types, and DDL details. Check the documentation for your database before running statements.
