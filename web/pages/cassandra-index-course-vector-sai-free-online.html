What Is a Storage-Attached Vector Indexes in Apache Cassandra?

Cassandra 5 SAI can index vector columns for approximate nearest-neighbor search. The coordinator selects candidates across distributed token ranges; vector similarity is distinct from partition-key equality.

Queries Supported by Storage-Attached Vector Indexes

Similarity search for embeddings in a Cassandra 5 deployment that supports SAI vector operations. A similar-looking predicate may not use the same access path; operators, expressions, key order, and data type all matter.

Read Performance, Storage, and Write Costs

Vector data and SAI consume substantial memory, disk, and CPU; replica fan-out and result quality need workload-specific testing. Indexes reduce some search work but require storage and add maintenance to writes.

Storage-Attached Vector Indexes Limitations and Common Mistakes

Storage-Attached Vector Indexes Questions

Will the database always use this index?

No. The optimizer weighs selectivity, estimated costs, statistics, cache state, and the amount of data returned.

What should I verify before production?

Confirm version support, query compatibility, write overhead, build/rollback procedures, and index behavior during backup and recovery.
