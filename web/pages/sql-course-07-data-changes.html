Lesson 7: Make changes inside a safe transaction

Practice data changes on a development database first. Use explicit column names, narrow predicates, and parameterized statements from application code.

BEGIN;
UPDATE orders
SET status = 'shipped'
WHERE order_id = 1042
  AND status = 'paid'
RETURNING order_id, status;
-- COMMIT after checking the returned row; otherwise ROLLBACK.

Safe change checklist

  1. Run a SELECT with the same WHERE clause and confirm intended rows.
  2. Use a transaction when the operation has multiple dependent steps.
  3. Check row counts and RETURNING results before commit.
  4. Use foreign keys and unique constraints to prevent invalid state.
  5. Use prepared statements for data supplied by users.
